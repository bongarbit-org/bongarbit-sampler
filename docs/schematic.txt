BONGARBIT SAMPLER — esquema reconstruído de pcb-artesanal.diy
================================================================
Gerado com a skill diy-netlist (~/.claude/skills/diy-netlist), a partir dos
traços/pads/labels do arquivo .diy. Convenção: nome do pad = texto mais
próximo dele no desenho; componente = retângulo (BlankBoard) cujo label
("DAC", "Micro SD", "ESP32-S3"...) está dentro dele.

Pontos marcados com (?) têm confiança menor - a perna do resistor ou do
sensor não fechou claramente na mesma rede do sinal correspondente durante
a reconstrução automática; confira no DIYLC antes de confiar.

Legenda
-------
──►   fio/trilha direta entre dois pontos
[ X ] botão / LED (componente de 2 pernas)
(( X )) disco piezoelétrico (não é um componente formal no .diy - a posição
        é inferida pelo label "Px" mais próximo; confira fisicamente)
R1..R4  resistores (R1-R3 = sangria 1M em paralelo com cada piezo,
        R4 = 220R em série com o LED)
(?)     baixa confiança - reconstrução automática não fechou claramente
        essa perna na mesma rede do sinal; revisar no DIYLC


Pinos usados (resumo)
----------------------
GPIO1  → piezo 1 (analog)         GPIO10 → SD MISO
GPIO2  → piezo 2 (analog)         GPIO11 → SD CLK/SCK
GPIO4  → botão B3                 GPIO12 → SD MOSI
GPIO5  → botão B2                 GPIO13 → SD CS
GPIO6  → botão B1                 GPIO16 → DAC BCK
GPIO7  → piezo 3 (analog) (?)     GPIO17 → DAC DIN
GPIO8  → "Sensor" (?, incompleto) GPIO18 → DAC LCK
GPIO41 → botão de modo (BM)
GPIO42 → LED de modo (LM), via R4 220R

Observação: neste arquivo B1/B2/B3 e BM/LM estão em pinos diferentes do
backup anterior (pcb-artesanal_backup.diy tinha GPIO4=B1/GPIO6=B3 e
GPIO41=LM/GPIO42=BM - aqui está invertido). Se este é o layout que vale,
o firmware ainda usa a numeração antiga (TRIGGER_PIN=4, padPins={5,6,7})
e não tem nada de piezo/BM/LM implementado - precisa reescrever antes de
gravar.
